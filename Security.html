Security Big Picture: CIA, Threats, Vulnerabilities, Risk

This section helps you write high-scoring “explain why security matters” answers.
Core

In Computer Science exams, security is not only “hackers”. It is about protecting data and systems so they remain confidential, accurate, and available. A good security answer usually includes: (1) the goal (CIA), (2) the threat, (3) the weakness (vulnerability), and (4) the control (solution).

CIA Triad (must know)

  • Confidentiality: only authorised people can read the data.
  • Integrity: data is correct and has not been altered without permission.
  • Availability: systems/data are accessible when needed.

Threat vs Vulnerability vs Risk

Threat: something that can cause harm (virus, attacker, fire).
Vulnerability: a weakness that allows the threat to succeed (weak password, unpatched OS).
Risk: likelihood × impact — often summarised as Risk = Threat × Vulnerability.
Exam sentence template:
“The threat is ______. The vulnerability is ______. This can cause ______ (impact on CIA). A suitable control is ______ because ______.”
Quick Practice (4 marks): Explain the difference between a threat and a vulnerability with an example. Core
Model answer:
A threat is something that can cause harm, such as a hacker or malware. A vulnerability is a weakness that makes the harm possible, such as using a weak password or not installing security updates. For example, the threat is a brute-force attack, and the vulnerability is a short password with no lockout policy.
Mark hint: 1 mark definition threat + 1 mark definition vulnerability + 2 marks for a linked example.

Threats & Attacks: Malware, Phishing, Social Engineering, DoS

Learn the “definition + how it spreads + effect + prevention” pattern.
Threats

A security threat can be technical (malware) or human (social engineering). Exams often ask you to identify the attack, explain how it works, then suggest controls.

Malware (general definition)

Malware means “malicious software”: software designed to harm a system, steal data, or take control. Common malware types differ in how they spread and what damage they cause.

Common exam method

For any threat: How it enters → What it does → Which CIA part is affected → Control.
🦠 Virus vs Worm (easy marks) Core
Virus: attaches to a host file/program and spreads when that file is executed (often needs user action).
Worm: self-contained program that copies itself automatically (often spreads across networks without user action).
Typical impacts: data corruption (integrity), slow system/network (availability), data leakage (confidentiality).
🎭 Trojan & Ransomware Very common
Trojan: malware disguised as a legitimate program. User installs it believing it is safe. Once installed, it may create a backdoor, steal data, or install more malware.

Ransomware: encrypts files and demands payment for decryption. Mainly affects availability of data, and can also impact integrity (files changed/encrypted).
Controls: backups (offline/immutable), patching, least privilege, user training, anti-malware.
🕵️ Spyware / Keylogger / Rootkit Higher marks
Spyware: secretly collects information (browsing habits, credentials).
Keylogger: records keystrokes to capture passwords and messages (confidentiality breach).
Rootkit: hides malware and gives attacker privileged access (hard to detect).
Controls: anti-malware, OS updates, least privilege, secure boot, monitoring.
🎣 Phishing & Social Engineering Must know
Phishing: fake messages (email/SMS/social media) that trick users into giving passwords or clicking malicious links. Often uses urgency (“Your account will be closed!”) and looks like a trusted brand.

Social engineering: manipulating people to break security rules (e.g., pretending to be IT support).
Controls: user training, verify sender, MFA, email filtering, do not click unknown links, check URLs.
🚦 Denial of Service (DoS / DDoS) Availability
DoS: makes a service unavailable by overwhelming it with requests or exploiting resource limits (CPU/memory/bandwidth).
DDoS: distributed DoS using many infected devices (botnet).
Controls: rate limiting, filtering, CDN, firewall rules, traffic scrubbing, redundancy.
Q1 (6 marks): Compare a virus and a worm and explain one control for each. Threats
Model answer:
A virus attaches to a host file/program and spreads when the infected program is executed, usually requiring user action. A worm is a standalone program that copies itself automatically, often spreading across networks without user action. A control for viruses is anti-virus software with real-time scanning and not running unknown executables. A control for worms is patching vulnerabilities and using firewalls/network filtering to block unauthorised traffic.
Mark hint: Marks for: host+execution vs self-copy+network + one suitable control each.
Q2 (6 marks): Explain phishing and give two methods to reduce its success. Threats
Model answer:
Phishing is a social engineering attack where fake messages impersonate trusted organisations to trick users into revealing credentials or clicking malicious links. Two methods to reduce it are user training (check sender/URL and avoid urgent requests), and using multi-factor authentication so stolen passwords alone are not enough. Email filtering and reporting suspicious messages also help.
Mark hint: Define phishing + 2 clear methods with reasons.

Authentication & Access Control: Proving Identity and Limiting Permissions

Exams often ask “authentication vs authorisation” and “MFA factors”.
Auth

Security is not only stopping attackers. It is also making sure the right people can access the right resources. This is done through authentication (prove who you are) and authorisation (what you are allowed to do).

Authentication vs Authorisation

Authentication: “Who are you?” (login, biometrics).
Authorisation: “What can you do?” (permissions/roles).

Example: You authenticate to the school portal, but authorisation decides whether you can edit grades.

Access control models (basic)

Least privilege: give users only the minimum permissions needed.
Role-based access control (RBAC): permissions are assigned to roles (teacher/student/admin).
🔑 Passwords (strength + policies) Common exam
A good password policy includes:
  • Minimum length (longer is stronger).
  • Mix of character types (upper/lower/digits/symbols).
  • Block common passwords and dictionary words.
  • Lockout / rate-limiting after repeated failures (stops brute-force).
  • Do not reuse passwords; use password manager.
🧬 Biometrics (pros/cons) Higher marks
Biometrics: fingerprint, face, iris, voice.
  • Pros: convenient, hard to guess/steal like a password.
  • Cons: false accept/reject rates, privacy concerns, cannot be changed if leaked (you can’t change your fingerprint).
🔐 Multi-Factor Authentication (MFA) Must know
MFA uses two or more factors from different categories:
  • Something you know: password, PIN.
  • Something you have: phone, token, smart card.
  • Something you are: biometrics.
It reduces risk because stealing one factor is not enough.
Q3 (6 marks): Distinguish authentication and authorisation, with an example. Auth
Model answer:
Authentication verifies a user’s identity, for example by checking a username and password or biometric scan. Authorisation decides what an authenticated user is allowed to do, such as whether they can view, edit, or delete files. Example: a teacher and student both authenticate to the school system, but only the teacher is authorised to edit marks.
Mark hint: 2 marks definitions + 2 marks example + 2 marks linking “identity vs permissions”.
Q4 (6 marks): Explain how MFA reduces the risk of unauthorised access. MFA
Model answer:
MFA requires two or more factors from different categories (something you know/have/are). Even if an attacker steals a password (something you know), they still need the second factor, such as a phone code (something you have) or fingerprint (something you are). This makes brute-force and phishing less effective because a single credential is not enough.
Mark hint: Mention factor categories + explain “one stolen factor not enough”.

Integrity: Hashing, Checksums, and Digital Signatures (conceptual)

Integrity = detect tampering. Hashes are a very common exam topic.
Integrity

Integrity means data has not been changed without permission. A core tool is a hash function, which takes an input (message/file/password) and produces a fixed-size output called a hash (digest). If the data changes, the hash changes a lot.

Hash function properties (exam-friendly)

  • Same input → same output (deterministic).
  • Small input change → big output change (avalanche effect).
  • Hard to reverse (one-way).
  • Hard to find two different inputs with same hash (collision resistance).

Hashing vs Encryption (important)

Encryption: reversible with a key (confidentiality).
Hashing: one-way, not meant to be reversed (integrity, password storage).
🧾 Checksums (simple integrity) Foundation
A checksum is a simple value calculated from data to detect errors during transmission/storage. If the checksum changes, data likely changed. Hashes are usually stronger than simple checksums.
🧂 Salting passwords (why?) Higher marks
If passwords are stored as hashes, attackers may use a rainbow table of precomputed hashes. A salt is a random value added to the password before hashing. This means the same password produces different hashes for different users, making rainbow tables far less effective.
✍️ Digital signatures (idea level) A Level extension
A digital signature helps prove integrity and authenticity. The sender hashes the message and signs the hash with their private key. The receiver verifies using the sender’s public key. This shows the message was not altered and came from the sender (non-repudiation in higher-level discussion).
Q5 (6 marks): Explain what hashing is and how it can be used for integrity checking. Hashing
Model answer:
Hashing uses a one-way function to convert data into a fixed-length hash (digest). The same input produces the same output, but even a small change to the input produces a very different hash. For integrity checking, the sender calculates the hash of a file/message and sends the data plus the hash. The receiver recalculates the hash and compares; if they match, the data is likely unchanged.
Mark hint: Define hash + fixed length + avalanche + comparison method.

Encryption: Symmetric vs Asymmetric (Public/Private Key)

This is a high-frequency exam area. Learn clear comparisons and use cases.
Encryption

Encryption protects confidentiality by converting plaintext into ciphertext using an algorithm and a key. Only someone with the correct key (or matching key) can decrypt and read the message.

Symmetric encryption

Uses one shared key for encryption and decryption (same key both ways).
Pros: fast, good for large data (files, streams).
Cons: key distribution problem (how to share the key safely?).

Asymmetric encryption

Uses a key pair: public key and private key.
Public key can be shared; private key must be kept secret.
Pros: solves key distribution, supports signatures.
Cons: slower than symmetric.
🔁 How hybrid encryption works (TLS idea) Must know
In real systems, asymmetric encryption is used to exchange a session key securely. Then symmetric encryption uses that session key to encrypt all further data (fast for large amounts).
Q6 (8 marks): Compare symmetric and asymmetric encryption and give one use case for each. Encryption
Model answer:
Symmetric encryption uses the same shared key for encryption and decryption. It is fast and suitable for encrypting large files or data streams, but it has the key distribution problem because the key must be shared securely. Asymmetric encryption uses a public/private key pair; the public key can be shared while the private key remains secret. It helps with secure key exchange and digital signatures but is slower. A use case for symmetric encryption is encrypting stored files or a VPN data stream; a use case for asymmetric encryption is exchanging a session key or encrypting a message to a recipient using their public key.
Mark hint: 3+ differences + 1 use case each.

Digital Certificates & TLS (HTTPS): Building Trust Online

Learn the CA concept and why HTTPS prevents “fake website” attacks.
TLS

A major internet problem is: “How do you know this public key really belongs to the website you want?” A digital certificate solves this by having a trusted organisation (a Certificate Authority or CA) vouch for identity.

Certificate basics (exam-friendly)

  • Certificate contains: website identity + website public key + CA signature.
  • Browser trusts the CA (CA certificates pre-installed).
  • Browser verifies CA signature → trusts the website public key.
🔒 What TLS/HTTPS achieves Core
TLS provides:
  • Confidentiality: encryption prevents eavesdropping.
  • Integrity: detects tampering in transit.
  • Authentication: certificates help confirm the server identity (reduce MITM risk).
🧠 Man-in-the-middle (MITM) and why certificates matter Higher marks
In a MITM attack, an attacker intercepts communication and pretends to be the server. Certificates prevent this because the attacker cannot produce a valid CA-signed certificate for the real site. The browser warns the user if the certificate is invalid or mismatched.
Q7 (6 marks): Explain how digital certificates help prevent a user connecting to a fake website. TLS
Model answer:
A digital certificate links a website’s identity to its public key and is signed by a trusted Certificate Authority (CA). When a browser connects via HTTPS, it receives the certificate and verifies the CA signature using the CA’s trusted public key. If valid and the domain matches, the browser trusts that the public key belongs to that website, reducing the risk of a man-in-the-middle or fake site presenting its own key. If invalid, the browser warns the user.
Mark hint: Mention CA, signature verification, identity↔key link, browser trust/warning.
