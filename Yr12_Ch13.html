1. User-Defined Data Types (UDTs)

Define • explain why used • design records/structs • model real data
Click to open/close ▾

Definition (must be exam-perfect)

A user-defined data type is a data type created by the programmer to store data in a form that matches the problem. Instead of using only built-in types (integer, real, string, boolean), a user-defined type lets you group related values or restrict values to a set that makes sense.

Examiner-friendly phrase: UDTs improve clarity and reduce errors by modelling real-world data directly.

Why UDTs are used

  • Readability: Code becomes easier to understand because variables represent meaningful “things”.
  • Maintainability: If the structure changes (e.g., add a field), you update it in one place.
  • Data integrity: You can restrict values (e.g., a set of valid grades) to prevent invalid data.
  • Organisation: Related pieces of data move together as one unit (useful for lists, files, databases).

Common UDT forms you should recognise

In school CS, “user-defined type” usually means one of these patterns:

Record / Struct Enumeration Set of valid values Composite type (record containing arrays)

Record / Struct (the most important UDT)

A record (sometimes called a struct) groups multiple fields (attributes) into one new type. Each field has its own data type.

TYPE Student DECLARE Name : STRING DECLARE Age : INTEGER DECLARE TutorGroup : STRING DECLARE Attendance : REAL ENDTYPE DECLARE s : Student s.Name ← "Mina" s.Age ← 15 s.TutorGroup ← "10A" s.Attendance ← 96.5
Marking tip: When defining a record, include field names + field types. When using it, show how to access a field (dot notation).

Enumeration (restricted set of values)

An enumeration creates a type where only a fixed list of values is allowed. This prevents invalid values.

TYPE Day = (Mon, Tue, Wed, Thu, Fri, Sat, Sun) DECLARE Today : Day Today ← Wed

If a student tries to store “Weds” or “Wednesday”, it can be rejected because it’s not in the allowed list.

Design approach (how to build a good UDT)

  1. Identify the real-world object you need to store (e.g., Book, Customer, Flight, SensorReading).
  2. List the attributes you must store (e.g., BookTitle, ISBN, Copies, Price).
  3. Choose correct field types (integer for counts, real for measured values, string for names).
  4. Add constraints if needed (enumeration for limited options, boolean for yes/no).
Common mistake: using STRING for everything. Examiners prefer correct types (INTEGER for count, REAL for measurements).

UDTs and collections (arrays of records)

Once you define a UDT, you can store many of them in an array. This is common when reading/writing data files.

DECLARE ClassList : ARRAY[1:30] OF Student ClassList[1].Name ← "Aya" ClassList[1].Age ← 16

This approach makes your program structure match real data: a class is a list of students; a shop is a list of products; etc.

Exam-style mini checklist

  • Can you define “user-defined data type” in one sentence?
  • Can you give a record example and show field access?
  • Can you explain one advantage (clarity) and one advantage (validation)?
  • Can you suggest correct field types for a scenario?

2. File Organisation Methods

Serial • Sequential • Direct/Random • Indexing • when each is suitable
Click to open/close ▾

What does “file organisation” mean?

File organisation describes how records are stored and accessed in a file. The same data can be stored in different ways depending on what operations you need: searching, updating, appending, or retrieving a single record quickly.

Exam phrase: File organisation affects access speed, update cost, and storage overhead.

Key words you must use correctly

  • Record: a group of related fields in a file (e.g., one student).
  • Field: one item inside a record (e.g., Name, Age).
  • Key field: a field used to identify a record (e.g., StudentID).
  • Master file: the main file of records (e.g., all customers).
  • Transaction file: a file of changes to apply (e.g., new orders).

2.1 Serial file organisation

In a serial file, records are stored in the order they are added. There is no intentional ordering by a key.

  • Advantages: simple to create; quick to append new records.
  • Disadvantages: searching for a specific record can be slow because you may need to check many records.
  • Typical use: logs (event logs), sensor readings, audit trails.
If you must find “one specific record” often, a pure serial file becomes inefficient.

2.2 Sequential file organisation

In a sequential file, records are stored in a sorted order using a key field (e.g., StudentID ascending). You process the file from start to end.

  • Advantages: efficient for batch processing (e.g., printing a report for all students); can stop early in some searches when keys are ordered.
  • Disadvantages: inserting a new record in the correct position may require rewriting the file.
  • Typical use: payroll lists, class lists, printed registers, sorted reports.
Example (sorted by StudentID): 1003 ... 1005 ... 1008 ... 1012 ...

2.3 Direct / Random access (sometimes called “relative” files)

With direct access, you can jump straight to a record location without reading all previous records. Usually this requires:

  • Fixed-size records or a method to compute an address (e.g., hashing), and
  • A way to map a key to a physical position in the file.
  • Advantages: very fast access to a specific record.
  • Disadvantages: more complex; may require extra storage (gaps, indexes).
  • Typical use: systems that frequently fetch one record (bank account lookup, library member lookup).
Think: “I know the key, I want the record immediately” → direct access.

2.4 Indexed sequential (best of both ideas)

An index is a separate structure that stores key values and pointers (addresses) to where records are. An indexed sequential file keeps records in key order (sequential) but also has an index so you can locate areas quickly.

Index entry: (Key, Pointer) (1003, address 0) (1008, address 200) (1015, address 400)
  • Advantages: faster searching than sequential; still good for processing in order.
  • Disadvantages: index must be maintained; extra storage overhead.

How to answer “Which file organisation is most suitable?”

Use this exam method:

  1. State the file organisation.
  2. Link to the key requirement (fast lookup / easy append / batch processing).
  3. Give one advantage that matches the scenario.
  4. (Optional) Mention why another method is worse.
Example: “A log file should be serial because new entries are added constantly and you rarely need instant access to a single old record.”

3. Floating-Point Representation

Click to open/close ▾

What problem does floating-point solve?

Integers are fine for whole numbers, but many real quantities need decimals (e.g., 3.14, 0.001, 1250000.0). We want a way to store very small and very large numbers efficiently. Floating-point does this by storing numbers in a form similar to scientific notation.

Scientific notation idea: 305,000 = 3.05 × 10^5 0.00072 = 7.2 × 10^-4

Core idea (mantissa + exponent)

A floating-point number is stored using two parts:

  • Mantissa (significand): holds the significant digits of the number (its precision).
  • Exponent: tells you the scale (how far to shift the “decimal point” in base 2).
Exam phrase: Mantissa controls precision; exponent controls range.

Binary floating-point (conceptual model)

In binary, “shifting the point” is done in base 2. A simplified representation is:

Value = Mantissa × (2 ^ Exponent)

Example idea: if mantissa is 1.101 (binary) and exponent is 3, the value is 1.101 × 2^3.

Normalisation (why we do it)

Normalisation means writing the mantissa in a standard form so there is exactly one non-zero digit before the binary point. This maximises the precision for a fixed number of mantissa bits.

Example (binary): 0.01101 × 2^5 is not normalised 1.101 × 2^3 is normalised (shift point right; decrease exponent)
In exams, if asked to “normalise”, you must adjust the exponent correctly when you shift the point.

Precision and rounding

Because mantissa has a limited number of bits, not all real numbers can be represented exactly. Many decimals become repeating patterns in binary, so they must be rounded.

  • Rounding error: the stored value is an approximation.
  • Accumulated error: repeated calculations can increase error (e.g., adding small rounding errors many times).
Example idea: a number like 0.1 (denary) cannot be stored exactly in many binary float systems, so calculations may show 0.30000000000004.

Range and overflow/underflow

Exponent bits limit how large or small numbers can be.

  • Overflow: result is too large for the exponent range.
  • Underflow: result is too small (close to 0) to represent properly.
If a question asks why a float result is wrong, mention: limited mantissa (precision) OR limited exponent (range).

Exam answers: “Why use floating-point instead of integer?”

  • Stores fractional values (decimals).
  • Can represent very large and very small numbers using exponent scaling.
  • Used in measurements, science, graphics, audio processing.

Exam answers: “One disadvantage of floating-point”

  • Not all values are exact → rounding errors.
  • Arithmetic can be slower than integer operations.
  • Comparisons can be tricky (two computed floats may not be exactly equal).
Best 1-mark phrase: Floating-point numbers are often stored as approximations, causing rounding errors.

End-of-chapter “exam language” recap

  • User-defined data type: type created by programmer to model real data.
  • Record/struct: UDT that groups fields of different types.
  • Serial file: records stored in order added; easy append; slow search.
  • Sequential file: records stored sorted by key; good for batch; costly insert.
  • Direct access: jump straight to record; fast lookup; more complex.
  • Floating-point: mantissa × 2^exponent; mantissa precision, exponent range; rounding errors possible.

Practice Set 2 — File Organisation Methods

Q6. Distinguish between a serial file and a sequential file. (4)
4 marks
Model answer
  • Serial: records stored in the order they are added; not sorted by key.
  • Sequential: records stored sorted by a key field (e.g., ID order).
  • Serial is easy to append; sequential insertion may require rewriting to keep order.
  • Sequential is better for processing/searching by key order than serial.
Q7. A hospital keeps a log of every temperature reading from a sensor every 5 seconds. Choose the best file organisation and justify. (3)
3 marks
Model answer

Use a serial file because new readings are continuously appended in time order and the main requirement is to store many new records quickly; instant access to a specific old record is not usually needed.

Q8. A bank system must retrieve a customer record instantly using AccountNumber. Choose the best file organisation and justify. (3)
3 marks
Model answer

Use direct/random access (or indexed sequential) because the system frequently fetches one record by key and must jump straight to the record location without reading through all records first.

Q9. Explain what an index is in file organisation. (2)
2 marks
Model answer

An index is a separate structure that stores key values and pointers/addresses to the location of the records in the file. It speeds up searching because the program can locate the correct area/record quickly.

Q10. Give one disadvantage of sequential file organisation. (1)
1 mark
Model answer

Inserting a new record in the correct sorted position may require rewriting/reorganising the file.

Practice Set 3 — Floating-Point Representation

Mantissa/exponent • normalisation • precision vs range • errors
Click to open/close ▾
Q11. State what is meant by “mantissa” in floating-point representation. (2)
2 marks
Model answer

The mantissa (significand) stores the significant digits/bits of the number. It determines the precision (how accurate the stored value can be).

Q12. State what is meant by “exponent” in floating-point representation. (2)
2 marks
Model answer

The exponent stores the power of the base (usually 2) used to scale the mantissa. It determines the range of values (how large/small the number can be).

Q13. Explain why floating-point numbers can be inaccurate. (2)
2 marks
Model answer

Because the mantissa has a limited number of bits, many real numbers cannot be stored exactly in binary and must be rounded. This causes rounding errors (and repeated calculations can accumulate error).

Q14. In one sentence: what does normalisation achieve? (1)
1 mark
Model answer

Normalisation puts the mantissa into a standard form to maximise precision for a fixed number of mantissa bits.

Q15. Give one disadvantage of floating-point representation. (1)
1 mark
Model answer

Floating-point values are often approximate, so rounding errors can occur (not all numbers are stored exactly).
