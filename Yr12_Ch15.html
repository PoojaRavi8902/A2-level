1. Compare RISC vs CISC

Instruction set • cycles per instruction • complexity • pipeline • code size
Click to open/close ▾

Definitions

RISC (Reduced Instruction Set Computer): uses a small, simple set of instructions, designed to execute quickly (often 1 clock cycle per instruction).

CISC (Complex Instruction Set Computer): uses a large set of instructions, including complex instructions that can do more in one instruction (often multiple cycles).

Best phrase: RISC simplifies hardware to increase speed; CISC reduces program size by using more powerful instructions.

Key comparison points (the ones examiners love)

  • Instruction complexity: RISC simple; CISC complex.
  • Number of instructions: RISC fewer; CISC more.
  • Instruction length: RISC often fixed length; CISC often variable length.
  • Execution: RISC often 1 cycle; CISC often multiple cycles.
  • Pipelining: RISC easier to pipeline due to uniform instructions.
  • Code size: RISC may need more instructions to do the same job; CISC may use fewer instructions.
  • Hardware complexity: RISC simpler CPU design; CISC more complex control logic.
Common mistake: “RISC always faster” — not always. Correct: RISC often enables higher throughput via pipelining; performance depends on implementation and workload.

Exam-style comparison paragraph (4–6 marks)

RISC uses a smaller set of simple, fixed-length instructions, often designed to run in a single clock cycle. This makes pipelining easier and can increase instruction throughput. However, more instructions may be needed for a task, increasing program length. CISC uses a larger instruction set with more complex, sometimes multi-cycle instructions, which can reduce program size but increases CPU complexity.

2. Parallel Processing Types

Why parallel? • multi-core • SIMD • distributed • GPU • pipeline idea
Click to open/close ▾

Definition

Parallel processing is using more than one processing unit to perform tasks at the same time to improve performance (speed/throughput) or handle large problems.

Exam phrase: Parallel processing divides a problem into smaller parts that can run simultaneously.

Types you should understand

  • Multi-core / multiprocessor: several CPU cores run different threads/tasks at the same time.
  • SIMD (Single Instruction, Multiple Data): one instruction applied to many data items simultaneously (common in GPUs/vector units).
  • Distributed processing: multiple computers/servers share work over a network (e.g., render farms, cluster computing).
  • GPU parallelism: many small cores handle large numbers of similar operations (graphics, AI, image processing).
  • Pipelining (conceptual): overlapping stages of instruction execution (not multiple instructions in one stage, but stages in parallel).

Benefits and limitations

  • Benefits: faster processing; handles bigger workloads; improves responsiveness (multitasking).
  • Limitations: overhead to split/coordinate tasks; not all problems can be parallelised; risk of contention (shared resources).
Good evaluation point: if a task has many dependencies (one step must finish before the next), parallel processing gives little benefit.

Everyday examples (use in answers)

  • Video rendering and image filters (SIMD/GPU)
  • Web servers handling many user requests (multi-core/distributed)
  • Scientific simulations (distributed clusters)

3. Virtual Machines (VMs)

Host vs guest • hypervisor • advantages & disadvantages • use cases
Click to open/close ▾

Definition

A virtual machine is a software-based computer that behaves like a real computer. It runs an operating system and applications in an isolated environment on a physical machine. A VM shares the physical hardware (CPU, RAM, disk) through a hypervisor.

Best phrase: A VM provides isolation while sharing the same physical hardware.

Key terms

  • Host machine: the physical computer running the virtualization software.
  • Guest machine: the virtual computer running inside the host.
  • Hypervisor: software that creates/manages VMs and allocates CPU, memory and storage.
Host (physical hardware) └─ Hypervisor ├─ VM 1 (Guest OS + apps) ├─ VM 2 (Guest OS + apps) └─ VM 3 (Guest OS + apps)

Advantages (exam points)

  • Isolation: problems in one VM are less likely to affect others.
  • Testing: safely try new software/OS without damaging the host.
  • Server consolidation: multiple servers on one physical machine reduces cost and energy.
  • Snapshots: revert to a previous state quickly.

Disadvantages (exam points)

  • Performance overhead: VMs can run slower due to virtualization.
  • Resource limits: RAM/CPU shared — too many VMs can cause slowdowns.
  • Complexity: managing hypervisors and VM images requires skill.
In evaluation questions, link to the scenario: “VMs are good for testing” OR “VM overhead may not suit real-time systems”.

Typical uses

  • Running a different OS on the same computer (e.g., Windows VM on Linux).
  • Testing malware safely in isolation (security labs).
  • Cloud computing: many virtual servers on large physical machines.

4. Boolean Algebra & Karnaugh Maps

Laws • simplification • SOP/POS idea • K-map grouping • common traps
Click to open/close ▾

Boolean algebra basics

Boolean variables take values 0 or 1. Common operators:

  • AND (·): output 1 if both inputs are 1
  • OR (+): output 1 if at least one input is 1
  • NOT (¯): inverts 0↔1

Core laws you must know (and use)

Identity: A + 0 = A A · 1 = A Null: A + 1 = 1 A · 0 = 0 Idempotent: A + A = A A · A = A Complement: A + Ā = 1 A · Ā = 0 De Morgan: (A · B)̄ = Ā + B̄ (A + B)̄ = Ā · B̄ Absorption: A + (A · B) = A A · (A + B) = A
Examiner tip: In simplification questions, show steps using a named law (even briefly). That’s where marks come from.

Karnaugh maps (K-maps) — what they are

A Karnaugh map is a visual way to simplify Boolean expressions by grouping 1s (for SOP) or 0s (for POS) in powers of 2: 1, 2, 4, 8… Adjacent cells wrap around the edges.

Biggest student error: grouping diagonally. Only horizontal/vertical adjacency counts (with wrap-around).

2-variable K-map layout (for A,B)

B 0 1 A 0 m0 m1 1 m2 m3

For 3–4 variables, Gray code order is used. Many exams use 4-variable K-maps.

How to simplify using a K-map (SOP method)

  1. Fill the K-map with 1s where the output is 1 (from truth table or minterms).
  2. Make the largest possible groups of 1s (size 1,2,4,8...). Groups can overlap.
  3. For each group, identify variables that stay the same; those form the simplified term.
  4. OR the terms together to get the simplified expression.
If asked “simplify”, you must reduce the number of literals/gates, not just rewrite.

End-of-chapter exam language recap

  • RISC: small simple instruction set; often fixed length; easier pipelining.
  • CISC: large complex instruction set; fewer instructions per task; more complex CPU.
  • Parallel processing: multiple processing units working simultaneously; types include multi-core, SIMD, distributed, GPU.
  • VM: software computer running guest OS on host via hypervisor; advantages isolation/testing; disadvantage overhead.
  • K-map: groups 1s/0s in powers of 2 to simplify expressions; adjacency includes wrap-around.

Q16. Explain why “RISC is always faster than CISC” is not always true. (3)
3 marks
Model answer

Performance depends on CPU implementation and workload. A CISC CPU may translate complex instructions into fast internal micro-operations and can benefit from caching and modern pipelines. 2 marks
Model answer

Contention occurs when multiple threads/cores try to use the same shared resource (e.g., memory bus, cache, file, lock) at the same time, causing waiting and reducing speedup.
