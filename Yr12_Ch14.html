1. Purpose of Protocols

Rules for communication • reliability • addressing • timing • error control
Click to open/close ▾

Definition (2-mark perfect)

A protocol is a set of rules that devices follow so they can communicate successfully over a network. These rules define how data is formatted, transmitted, received, and checked.

Examiner-friendly phrase: Protocols ensure different devices and software can communicate reliably and consistently.

Why protocols are needed (what marks are awarded for)

Protocols prevent confusion by agreeing on:

  • Data format: how bits/bytes are grouped (frames, packets) and what headers mean.
  • Addressing: how sender/receiver are identified (IP address, MAC address, port number).
  • Timing & order: when to send, how fast, and how to reassemble in the correct order.
  • Error detection/correction: how to detect corruption and what happens next (retransmission).
  • Flow control: preventing a fast sender from overwhelming a slow receiver.
  • Security: how data can be encrypted and verified (e.g., HTTPS/TLS).
Common exam mistake: saying “protocols are needed to connect to the internet” (too vague). Always mention rules + at least one specific rule area (format, timing, error control, addressing).

Real examples you can drop into answers

You don’t need deep technical detail, but you should know what each does:

  • HTTP / HTTPS: rules for requesting and sending web pages.
  • TCP: reliable delivery (acknowledgements, retransmission, correct order).
  • IP: addressing and routing across networks.
  • DNS: converts domain names to IP addresses.
Exam phrasing: “For example, TCP uses acknowledgements to confirm packets arrived, so lost packets can be resent.”

Mini worked explanation (3–4 marks)

Question style: “Explain the purpose of protocols on a network.”

A protocol is a set of rules for communication. It defines how data is formatted and addressed so different devices understand it. It can include error control and acknowledgements so data is delivered reliably. This ensures consistent communication between devices made by different manufacturers.

2. TCP/IP Model

Layers • roles • encapsulation • examples of protocols at each layer
Click to open/close ▾

Big idea

The TCP/IP model is a layered way to describe how data moves across networks. Each layer has a clear job. Layering makes networks easier to design, troubleshoot, and update.

Examiner-friendly phrase: Each layer provides services to the layer above and uses services from the layer below.

TCP/IP layers (common 4-layer version used in school)

1) Application layer 2) Transport layer 3) Internet layer 4) Link (Network Access) layer

Some textbooks split Link into Data Link + Physical. For exam answers, stick to the 4 layers unless your teacher specifies otherwise.

Layer roles + examples

  • Application layer: services used by applications (web, email). Examples: HTTP/HTTPS, SMTP, FTP, DNS.
  • Transport layer: end-to-end communication, reliability, flow control. Examples: TCP (reliable), UDP (faster, less overhead).
  • Internet layer: addressing and routing between networks. Example: IP.
  • Link layer: moving frames on the local network and physical connection. Examples: Ethernet, Wi-Fi (conceptual).
Common confusion: IP is not responsible for reliability. IP routes packets; TCP can provide reliability.

Encapsulation (exam favourite)

As data goes down the layers, each layer adds its own header information. This is called encapsulation. At the receiver, headers are removed in reverse order (decapsulation).

Application data ↓ (Transport adds TCP header) => Segment ↓ (Internet adds IP header) => Packet ↓ (Link adds frame header/trailer) => Frame ↓ (Physical sends bits)
Quick marks: define encapsulation + state “headers added at each layer” + mention reverse at receiver.

Worked web example (from URL to page)

  1. You enter a URL in a browser.
  2. Application layer uses DNS to find the server IP address.
  3. Browser uses HTTP/HTTPS to request the page.
  4. Transport layer uses TCP to send reliably (acknowledgements, retransmission).
  5. Internet layer uses IP to route packets to the server.
  6. Link layer uses Ethernet/Wi-Fi to deliver frames across local links.

3. Packet Switching vs Circuit Switching

How each works • pros/cons • when to use • exam comparison structure
Click to open/close ▾

Packet switching (how it works)

In packet switching, data is broken into small units called packets. Each packet can travel independently across the network. Packets may take different routes and can arrive out of order; the destination reassembles them.

  • Each packet includes headers (source/destination address, sequence number, error checks).
  • Routers forward packets based on addressing.
Best exam phrase: Packet switching shares network links efficiently because many users can interleave packets.

Circuit switching (how it works)

In circuit switching, a dedicated communication path is set up between sender and receiver before data is sent. The path stays reserved for the whole session, then is released.

  • Predictable performance (reserved bandwidth).
  • But the circuit is wasted if no data is currently being sent.

Comparison table (use this structure in 4–6 mark answers)

Packet switching: • Data split into packets; packets may take different routes • Efficient use of network (shared links) • Variable delay; packets can arrive out of order • Suits the internet, email, web browsing, file transfers Circuit switching: • Dedicated path set up then used for whole session • Fixed bandwidth; predictable delay once connected • Setup time required; inefficient if circuit idle • Suits traditional voice calls / real-time dedicated links
High-mark answers must include: how it works + one advantage + one disadvantage + example use.

Quality/latency idea (evaluation)

Packet switching can have variable latency during congestion because packets compete for links. Circuit switching can provide stable performance after setup because resources are reserved.

If a question mentions “congestion” or “many users”, packet switching discussion should include queues, delays, and possible packet loss/retransmission.

End-of-chapter exam language recap

  • Protocol: agreed rules for communication (format, addressing, timing, error control).
  • TCP/IP model: layered network model; each layer has a role.
  • Encapsulation: headers added at each layer; removed in reverse at receiver.
  • Packet switching: split data into packets; shared links; variable delay; packets may arrive out of order.
  • Circuit switching: dedicated path reserved for session; predictable; inefficient if idle; setup time.

Q2. Describe encapsulation in the TCP/IP model. (3)
3 marks
Model answer

Encapsulation is the process where each TCP/IP layer adds its own header information to the data as it passes down the stack. This creates units such as segments, packets and frames. At the receiver the headers are removed in reverse order (decapsulation).

Q3. Compare packet switching and circuit switching. (6)
6 marks
Model answer

Packet switching splits data into packets that can take different routes and be reassembled at the destination. It uses shared links efficiently but can have variable delay and packets may arrive out of order during congestion. It suits the internet (web, email, file transfer).

Circuit switching establishes a dedicated path before sending data and reserves bandwidth for the session. This gives predictable performance after setup but wastes resources if the circuit is idle and has setup time. It suits traditional voice calls or dedicated connections.

Q13. Scenario: Video call in heavy congestion. Which switching is better and why? (4)
4 marks
Model answer

A dedicated circuit would give more predictable bandwidth and delay once connected, which helps real-time voice/video quality. However, modern internet video calls typically use packet switching; during congestion packets may be delayed or lost, causing jitter. A good answer explains the trade-off: predictable performance vs efficient sharing and practicality on the internet.
